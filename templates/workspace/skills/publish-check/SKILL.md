# publish-check：发布前检查

## 何时使用
用户说「检查一下」「检查发布」「过一遍」，或流水线进入阶段 6。

## 输入
- `projects/<最新项目>/draft.md`、`carousel.md`、`publish.md`、`facts.md`
- 涉及投资/公司/财报时叠加 `knowledge/investment/decision-framework.md` 的合规条款

## 检查项（逐项输出 PASS / FAIL + 依据 + 修改建议）

1. **事实**：正文每个数字/日期/公司名/事件与 facts.md 一致；无来源的数字标 FAIL；「待核」事实不得出现在正文。
2. **标题**：≤ 20 字；有钩子（数字/悬念/反常识/痛点）；无标题党承诺；有 3 个备选时标注推荐。
3. **可读性**：段落 3–5 行；句子 ≤ 30 字；术语已解释；emoji 每段 ≤ 2 个；全文 400–800 字。
4. **判断质量**：观点句有「我认为/看起来」等标记；事实与观点分离；有反方视角；无绝对化表述（一定/必然/稳赚）。
5. **空话检测**：扫描禁用词（深度好文/赋能/格局打开/干货满满/震惊/必看/速看/你懂的）；检查「很/非常/真的」等弱词是否可删；每段是否都在推进信息。
6. **合规**（涉及时）：投资类结尾有风险提示；无荐股/收益承诺；数据口径（时间、币种、基准）完整。
7. **图文一致性**（有 carousel.md 时）：图文信息与正文一致；封面标题 ≤ 12 字。

## 输出格式
- 逐项：`[PASS|FAIL] 项名 — 依据 — 修改建议`
- 总评：`可发布` / `修改后发布（列出必改项）` / `不建议发布（原因）`
- 结果写入 `projects/<最新项目>/publish.md`
