# xhs-writing：小红书文字版写作

## 何时使用
用户说「做成小红书」「写正文」「出文字版」，或流水线进入阶段 4。

## 输入（先读，再写）
1. `projects/<最新项目>/thesis.md` — 核心观点（一句话主张 + 证据 + 反方）
2. `projects/<最新项目>/draft.md` — 已有草稿（如有）
3. `projects/<最新项目>/facts.md` — 事实表（只写已核事实）
4. `knowledge/brand-voice.md` — 语感规范（写作前必读）

若项目文件不存在，先说明缺什么再动手；不凭空写。

## 输出结构
1. **标题 ×3**：每个 ≤ 20 字，注明钩子类型（数字/悬念/反常识/痛点），标注推荐项。
2. **正文 400–800 字**：
   - 开头钩子（1–2 句，点出矛盾或反常识）
   - 背景交代（≤ 3 句）
   - 核心分析（2–4 段，每段一个要点，数据落地，术语带解释）
   - 反方视角（1 段）
   - 结尾：判断框架/清单 + 开放问题
3. **话题标签 5–8 个**：2–3 个宽标签 + 2–3 个垂直标签 + 1–2 个话题性标签。
4. **合规标注**：投资/公司/财报内容必须附风险提示（见 investment-judgment）。

## 规则
- 事实只来自 facts.md 中状态为「已核」的条目；「待核/存疑」不得入稿。
- 观点句必须有「我认为/看起来/大概率」等标记，不冒充事实。
- emoji 每段 ≤ 1–2 个；禁用词见 brand-voice.md。
- 写完更新 `draft.md`，并自检一遍再交付。
